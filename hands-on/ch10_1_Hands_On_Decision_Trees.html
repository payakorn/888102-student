Hands-on 10.1 · before the first line of code

The code runs in the browser Every code box is live. Press Run Code (or Ctrl/⌘ + Enter inside the box) and the result appears below it. Nothing is installed on the computer.

The session in four parts

Hands-on 10.1 · roadmap

Part 10.1 grew a decision tree from fourteen golf days by counting, drew it, and read it as five rules. This session hands the same job to a library: scikit-learn grows the tree in one command, draws it in another, and the rest of the time goes to reading what it grew.

A · The golf days, with the toolThe fourteen days as a table; the text values turned into numbers; the tree grown and drawn in one command each; read as text; asked about a new day; scored on its own days.
B · A real dataset150 iris flowers bundled with scikit-learn: the library grows the tree one question deep and then two, draws it, and predicts a new flower.
C · ExercisesFour graded exercises on the two datasets, each with a hint and a solution.
D · Where this leaves usThe tree scores 100% on its own days. Part 10.2 asks what it scores on days it has not seen.

Three commands DecisionTreeClassifier().fit(X, y) grows the tree from the features X and the target y. plot_tree(model) draws it. model.predict(new_rows) walks new cases through it. Everything else on these slides is preparing the data and reading the result.

The fourteen golf days

Hands-on 10.1 · A · the training data

Labelled data The fourteen days go into a pandas table, one row per day: four features — outlook, temperature, humidity, wind — and one target, whether golf was played. The row numbers are set to 1 to 14 so they match the day numbers.

FEATURES keeps the four feature names in a list.

Interpretation Fourteen rows, five columns. Every row already carries its answer in the last column — that is what lets a tree be grown from it.

Nine Yes, five No

Hands-on 10.1 · A · the whole table as one group

Before any question is asked, the whole table is one group. value_counts() counts how many days fall in each class of the target.

Interpretation Nine Yes and five No. The group is mixed, so a question is needed. A tree that asked nothing would say Yes for every day and be right nine times in fourteen; every question the tree asks is an attempt to do better than that.

Text to numbers

Hands-on 10.1 · A · what the library needs

scikit-learn only takes numbers. pd.get_dummies turns each text column into one 0/1 column per value: outlook becomes outlook_Overcast, outlook_Rainy, outlook_Sunny, and a rainy day has a 1 in the second and 0 in the other two. The target can stay as text.

Interpretation

  • Ten columns from four: three for outlook, three for temperature, two for humidity, two for wind.
  • Day 1 — Rainy, Hot, High, not windy — reads 0 1 0 · 0 1 0 · 1 0 · 1 0. Every row has exactly one 1 in each group of columns.
  • A question on such a column — “is outlook_Overcast 1?” — is a yes/no question about one value.

The tree in one command

Hands-on 10.1 · A · grown and drawn

DecisionTreeClassifier().fit(X, y) grows the tree: the features and the target go in, the model comes back. plot_tree draws it with matplotlib; in the browser the drawing is saved as a picture file and the picture is shown. Two commands, and the whole of Part 10.1’s algorithm has run.

Interpretation

  • Each box is a group of days. samples is how many; value is the count of [No, Yes] among them; class is the majority. The color is the majority’s, darker the purer the group.
  • The question is the first line, and a true answer goes left. outlook_Overcast <= 0.5 means “not overcast”: the ten other days go left, the four overcast days go right — and that right box is a pure leaf, Yes.
  • A box with no question is a leaf. Every leaf here is pure: the growing stopped when nothing was left to sort.

The tree as text

Hands-on 10.1 · A · the same tree, one rule per line

export_text prints the same tree with one level of indentation per question — the form to copy into a report or a program.

Interpretation

  • The first question is the same as in the tree of Part 10.1, drawn here: outlook, and overcast is a pure leaf at once.
  • The rest is deeper: four questions and seven leaves against two and five. A 0/1 column asks about one value at a time, so the three-way outlook takes two questions, and the library scores a question with a formula for how mixed the groups are rather than by counting settled days.
  • Both trees agree with all fourteen days. Different roads, same destination.

Predicting a new day

Hands-on 10.1 · A · deduction

.predict() walks new rows through the tree. A new day must be written in the same ten 0/1 columns as the training data, so a small helper turns a day’s four values into that row — reindex lines the columns up and fills the missing ones with 0.

Interpretation Do not play. On the drawing the day goes left at the root (not overcast), left again at humidity (not normal), left at outlook_Rainy (not rainy), and left at windy_No (it is windy) — a leaf of two days, both No.

Try it Change the outlook to "Overcast" and run: Yes, at the first question. Change it to "Rainy" with "Normal" humidity: Yes again.

The tree on its own fourteen days

Hands-on 10.1 · A · training accuracy

.score(X, y) runs every training day back through the tree and returns the share it gets right. The second line writes the tree’s answer beside each day’s true one.

Interpretation 100%. Every leaf agrees with its days, because the algorithm kept asking questions until every group was pure. That is how well the tree fits the days it was grown from; it is not yet evidence of how well it predicts a day it has not seen. Part 10.2 measures that.

A real dataset — 150 iris flowers

Hands-on 10.1 · B · the same commands on real data

Fourteen rows can be checked by hand. Real datasets cannot, and here the library earns its place. The dataset comes with it — no file to download.

The data 150 iris flowers measured by the botanist Edgar Anderson and published by Ronald Fisher in 1936: 50 of each of three species, and four measurements of each flower in centimeters — the length and width of the sepal (the outer leaf) and of the petal.

The question Can a flower’s species be told from its four measurements, and what rules does the tree find? The target is the species — three classes, so a multi-class problem. The features are the four measurements.

What changes The features are already numbers, so no 0/1 columns are needed. A question becomes a cut-point — “petal width ≤ 0.8?” — and the library tries cut-points the way it tried the 0/1 columns.

Where the dataset comes from sklearn.datasets bundles several small real datasets with the library: load_iris (the flowers), load_breast_cancer (569 tumors, used in Part 10.2), load_diabetes (442 patients, used in Part 10.3), load_wine, load_digits. Each loads in one line and works offline once the library is present.

Loading the flowers

Hands-on 10.1 · B · the data as a table

load_iris(as_frame=True) returns the measurements as a pandas table and the species of each flower as a number 0, 1, 2, with the names in a separate list. The columns are renamed to short names and a species column with the names is added.

Interpretation 150 rows and 5 columns: four measurements in centimeters and the species. The first flowers are all setosa, because the file is sorted by species.

Three species, fifty each

Hands-on 10.1 · B · the whole table as one group

As with the golf days, the whole table is first one group, and the count of each class says how mixed it is.

Interpretation 50 setosa, 50 versicolor, 50 virginica. A tree that asked nothing would be right one time in three.

The first question the library chooses

Hands-on 10.1 · B · a tree one question deep

max_depth=1 limits the tree to one question. .fit(X, y) is the same training step as before; export_text prints the result.

Interpretation

  • One question — petal width ≤ 0.8 cm — sends every setosa left and every other flower right.
  • The left group is pure, like the overcast leaf of the golf tree.
  • The right group still mixes versicolor and virginica, so it needs another question.

A tree two questions deep

Hands-on 10.1 · B · one more question inside the mixed group

Raising max_depth to 2 lets the algorithm ask one more question inside the mixed group. .score(X, y) is the share of the 150 flowers the tree gets right — the training accuracy.

Interpretation

  • The second question is petal width again, at 1.75 cm: at most 1.75 is called versicolor, above it virginica.
  • Three leaves and 96% on the training flowers. The two right-hand leaves are not pure: six flowers land in a leaf whose answer is not their species.

Try it Set max_depth=3 and run again. One more question on each side, and the accuracy rises to 97.3%. Exercise 3 returns to this.

The tree, drawn

Hands-on 10.1 · B · the same command as for the golf days

plot_tree draws the iris tree exactly as it drew the golf tree. With numeric features the question in each box is a cut-point, and value now counts three classes: [setosa, versicolor, virginica].

Interpretation

  • The root holds all 150 flowers, 50 of each; its question is petal width ≤ 0.8.
  • The left leaf is pure setosa, so it is drawn in a solid color. The right node holds 100 flowers and asks petal width ≤ 1.75.
  • The two bottom leaves are paler: 49 versicolor with 5 virginica in one, 45 virginica with 1 versicolor in the other — the six flowers behind the 96%.

Predicting a new flower

Hands-on 10.1 · B · deduction, with cut-points

.predict() walks a new flower through the tree. The flower is written as a one-row table with the same four columns, in the same order, as the training data — no helper needed, because the features are already numbers.

Interpretation Versicolor. Its petal width of 1.5 cm fails the first test (more than 0.8) and passes the second (at most 1.75), so it lands in the versicolor leaf — the same walk as the sunny, windy day, with cut-points in place of 0/1 columns.

The golf tree and the iris tree

Hands-on 10.1 · B · one tool, two kinds of data

The golf tree — Part A Four categorical features, turned into ten 0/1 columns first. A question asks about one value — “is it overcast?” — and a new day has to be encoded the same way before it is predicted. Fourteen rows: every box on the drawing can be checked against the table.

The iris tree — Part B Four numeric features, used as they are. A question is a cut-point on one feature — “petal width ≤ 1.75?” — and a new flower is a row of four numbers. 150 rows: the drawing is the only way to see the whole tree.

What is the same The three commands. DecisionTreeClassifier(...).fit(X, y) grows the tree, plot_tree and export_text show it, .predict walks a new case through it — and the tree is read the same way in both cases: root to leaf, one question per box, one rule per path.

Exercise 1 — a golf tree two questions deep

Hands-on 10.1 · C · depth and training accuracy

The full golf tree asked four questions and scored 100%. Grow one that may ask only two, and return its training accuracy rounded to four decimals. The last line must be the expression itself, not a print.

max_depth is the number of questions on the longest path from the root to a leaf. The full tree used 4; this one may use 2.

small_tree = DecisionTreeClassifier(max_depth=2, random_state=0).fit(X_golf, y_golf)
round(small_tree.score(X_golf, y_golf), 4)

0.8571: 12 of 14. Add print(export_text(small_tree, feature_names=list(X_golf.columns))) above the last line to see the two questions it kept.

Exercise 2 — a rainy day with normal humidity

Hands-on 10.1 · C · a new day through the tree

The rule for this day in Part 10.1 reads IF rainy AND humidity normal THEN play. Fill the two blanks so the day is rainy with normal humidity, and let the library’s tree answer. Temperature and wind may be anything on this path.

The values must be written exactly as in the table: "Rainy" for the outlook, "Normal" for the humidity, with the capital letter.

day = {"outlook": "Rainy", "temp": "Cool", "humidity": "Normal", "windy": "No"}
golf_tree.predict(encode(day))[0]

'Yes'. Days 9 and 11 are the two training days that are rainy with normal humidity, and both were played.

Exercise 3 — a deeper iris tree

Hands-on 10.1 · C · depth and training accuracy

The tree two questions deep scored 96% on the 150 flowers. Grow a tree three questions deep and return its training accuracy, rounded to four decimals. The last line must be the expression itself.

max_depth is the number of questions on the longest path from the root to a leaf. The tree of the slides used 2; this one uses one more.

tree3 = DecisionTreeClassifier(max_depth=3, random_state=0).fit(X, y)
round(tree3.score(X, y), 4)

0.9733 — 146 of 150. Add print(export_text(tree3, feature_names=list(X.columns), class_names=list(tree3.classes_))) above the last line to read the third question: petal length, at 4.95 cm on one side and 4.85 cm on the other.

Exercise 4 — a new flower

Hands-on 10.1 · C · deduction with the library

A flower has sepal length 6.7, sepal width 3.0, petal length 5.2 and petal width 2.3 cm. Fill the blank with its petal width and let the tree two questions deep name its species.

The four columns are, in order, sepal length, sepal width, petal length, petal width. The blank is the fourth value.

new_flower = pd.DataFrame([[6.7, 3.0, 5.2, 2.3]], columns=X.columns)
tree2.predict(new_flower)[0]

'virginica': petal width 2.3 fails ≤ 0.8 and fails ≤ 1.75, so the flower goes right twice.

What to keep from the session

Hands-on 10.1 · D · takeaways

Three commands DecisionTreeClassifier(max_depth=…).fit(X, y) grows the tree; plot_tree draws it and export_text prints it; .predict walks a new case through it. The algorithm of Part 10.1 runs inside the first one.

Prepare the data, then read the tree Text features become 0/1 columns with pd.get_dummies; numbers are used as they are. Reading the drawing — the question, samples, value, class — is where the understanding is.

100% on its own days proves nothing yet The golf tree fits every day it was grown from, and each extra question raised the iris tree’s training score. Part 10.2 asks the tree about days and flowers it has not seen.

Take-home The Chapter 10.1 notebook for Colab carries the counting version of the tree — the algorithm written out step by step — as well as the library, with the graded homework on the iris flowers. Work there keeps; this page forgets when it is reloaded.

Where this leaves us Two trees were grown, drawn and read, one from fourteen days and one from 150 flowers. Nothing has yet been said about how good either is. The hands-on of Part 10.2 holds days back, asks the tree about them, and counts the four boxes.
